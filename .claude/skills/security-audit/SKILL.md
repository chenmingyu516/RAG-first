# 安全审查（security-audit）

本技能用于审查代码与配置的**安全隐患**，从以下四个方面检查，输出中文报告。

## 四大检查项

### 1. 敏感信息泄露

- 检查代码中是否**硬编码**了密码、密钥、Token、API Key、数据库连接串等敏感信息。
- 常见关键词/形态：`password`、`passwd`、`secret`、`token`、`api_key`、`access_key`、`private_key`、`BEGIN PRIVATE KEY`、含账号密码的连接串等。
- 特别提醒：本项目 `backend/.env` 里的 `DASHSCOPE_API_KEY`、`JWT_SECRET` 属于敏感信息，应确认 `.env` 已被 `.gitignore` 忽略，不会进版本库。

### 2. SQL / 命令注入等漏洞

- 检查所有 SQL 是否使用**参数化查询**，而不是字符串拼接。
  - 本项目后端用 SQLAlchemy，应使用 `db.query(...).filter(Model.field == 变量)` 等参数化写法，**不得**出现 `f"... WHERE x='{变量}'"` 这类拼 SQL 的写法。
- 检查是否存在**命令注入**：Python 里 `os.system`、`subprocess.run(..., shell=True)` 拼接用户输入。
- 检查**路径穿越**：把用户输入直接拼成文件路径（如上传文件名）。

### 3. 配置文件明文敏感信息

- 检查 `.env`、`*.config.*`、yml/json 等配置文件里是否含明文密码/密钥。
- 检查这些配置文件是否被 `.gitignore` 正确忽略，避免把密钥提交进版本库。

### 4. 其它安全隐患（结合本项目是 Python + Vue 的 Web 应用）

- FastAPI 接口是否缺少鉴权（本项目的知识库管理接口应只允许 admin）。
- JWT 密钥是否过弱、令牌是否设置了过期时间。
- 前端是否对用户输入/模型输出做转义（防 XSS）；本系统答案用 DOMPurify 做了消毒，需确认保持。
- CORS 配置是否过宽（生产环境不应 `allow_origins=["*"]`）。
- 依赖是否存在已知高危漏洞（可结合 `npm audit` 检查前端依赖）。

## 执行步骤

1. **确定范围**：默认检查当前未提交的改动（`git diff`）；用户可指定文件/目录/全项目。
2. **逐项检查**：按上面四大项检查，可结合 `Grep` 搜索敏感关键词。
3. **输出中文报告**。

## 报告格式（中文）

- **一、检查范围**
- **二、敏感信息泄露**：按「文件:行号 —— 问题 —— 建议」列出
- **三、注入等漏洞风险**：同上
- **四、配置文件明文敏感信息**：同上
- **五、其它安全隐患**：同上
- **六、总体结论**：风险等级（高 / 中 / 低）+ 一句话总结

## 注意事项

- 只做审查 + 报告，默认**不改代码**；用户明确要求修复时再动手。
- 按严重程度排序，高危问题放最前。
- 报告具体、可操作，不泛泛而谈。
- 报告里如出现真实密钥等敏感信息，应做**脱敏**处理（打码）。
